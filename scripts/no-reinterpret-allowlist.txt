# scripts/no-reinterpret-allowlist.txt — grandfathered reinterpret_cast sites.
#
# Format: `path:text` (one per line, relative to project root).  `text`
# is the EXACT trimmed source of the violating call line (leading and
# trailing whitespace stripped) — a content key, NOT a line number.
# Comments start with '#'.  Blank lines ignored.
#
# fix-18: content-keying replaces the legacy `path:line` form.  A line
# number drifts the instant ANY edit lands above the call (a concurrent
# agent inserting a member, a new `#include`, a reflowed comment),
# silently staling the entry: the real reinterpret_cast reads as
# un-suppressed AND the dangling line-keyed entry trips the stale gate.
# The call line's TEXT is stable across line shifts.  Mirror of the
# name-keyed mint-pattern guard (mint-pattern-allowlist.txt).
#
# Every entry is a TODO awaiting a tracked migration.  When the
# referenced FIXY-U-082 / fixy-A5-028 / WRAP-* ticket lands, delete the
# line — the guard then catches any future drift.  Stale entries (no
# matching call text in the file) red CI at exit 2 so the allowlist
# drains in lockstep with substrate fixes.
#
# Inline suppression (preferred for new code): `// NO-REINTERPRET-OK:
# <reason>` on the call line exempts that single line directly.
#
# The include/ tree carries no grandfathered sites — FIXY-U-082
# drained the cntp/Fec + AfXdp + Integrity + GpuDirect cluster and it
# has stayed drained.  The entries below are vessel/, not include/.
#
# ── vessel/ COVERAGE EXTENSION — NOT pre-approved ───────────────────
#
# The entries below were NOT reviewed and NOT granted a waiver.  They
# are the 5 pre-existing reinterpret_cast sites the guard surfaced the
# moment `vessel/` entered its scan set.  Until that change `vessel/`
# was absent from `scan_dirs`, so the PyTorch adapter — production C++
# sitting on the C ABI boundary — was never checked at all.  No rg
# glob had to be dropped: none of the existing exclusions (`build`,
# `cmake-build-*`, `third_party`, `external`, `vendor`, `test`,
# `bench`, `examples`) ever matched vessel/.  They are grandfathered
# only so the coverage extension lands green.
#
# Status: awaiting triage.  Two shapes are present:
#
#   (a) Pointer→integer for a debug plausibility check or a cache-index
#       hash (vessel_api_typed.h, crucible_fallback.cpp — the entries
#       below carry the call text, which is the stable key; line numbers
#       are left out of this prose because they drift and this comment
#       is not checked against anything).
#       `std::bit_cast<std::uintptr_t>(ptr)` is the §III replacement
#       and is a mechanical swap.  Two of the three are inside
#       `#ifndef NDEBUG` blocks, so they carry no release-build cost —
#       that bounds the urgency, it does not grant an exemption.
#
#   (b) Layout-compatible pointer view changes between CrucibleMeta and
#       crucible::TensorMeta (vessel_api_typed.h:172/176).  These are
#       NOT bit_cast-able (bit_cast needs same-size values, not a
#       pointer view change) and are the substantive open question.
#       The header pins the layout with offsetof/sizeof static_asserts
#       immediately above the casts, which is real evidence the punning
#       is sound — but a proof of layout compatibility is not the same
#       as a §III waiver, and no reviewer has signed off on one.
#
# On vessel_api.cpp: that file carries a file-level comment (line 17)

# comment says, because it is the opposite of a self-granted waiver.

# is that comment, which the guard's comment filter drops, so
# vessel_api.cpp contributes zero live sites and gets zero entries

#
