# frozen-soundness-mirrors — the reviewed changes to the frozen tree.
#
# check-frozen-tree.py freezes the old substrate: nothing is added to it
# and nothing in it is modified, until it is deleted.  A row of this file
# admits one reviewed change to a frozen file.  Usually the change mirrors
# a soundness fix that the new tree already holds, because the old code
# keeps the bug until the old tree is deleted.
#
# Format, one row per line:
#
#   path — keys — new-tree fix — reason
#
#   path           the frozen file that the change edits.  It must be under
#                  a frozen directory and it must exist.
#   keys           the hunks of the change, separated by commas.  A key is
#                  the first 16 hex digits of the SHA-256 of one hunk of the
#                  line diff between the base twin and the file: the removed
#                  lines prefixed "-" and the added lines prefixed "+".  Two
#                  hunks with the same text take the key two times.  Run
#                  check-frozen-tree.py --mirror-hunks PATH to print them.
#   new-tree fix   a path or a commit that shows the fix in the new tree.
#   reason         the defect, in one clause.
#
# A row admits its hunks and no other change.  A second edit to the file
# makes a hunk that no row keys, and the guard fails.  An edit next to a
# keyed hunk changes the text of that hunk, and the guard fails too.  A key
# that matches no hunk of its file fails the guard, so a row goes, or gets
# new keys, when its change goes.  The removal of an include of a header
# that the same change deletes or marks needs no row.  A comment starts
# with '#'.  A blank line is skipped.
