# port-drops — superseded-header symbols that deliberately have no home
# in the new tree.
#
# scripts/check-port-completeness.sh enumerates every public symbol of
# every `_Foo.h` under include/crucible/ (the underscore is the superseded
# marking, so that set is exactly what the project claims to have ported)
# and requires each to exist by name under include/foundation/ or
# include/fixy/.  A symbol that was not carried on purpose is listed here
# with one sentence saying why.  A symbol that is neither present nor
# listed is a missing port and fails the guard.
#
# Each entry is `<header>:<symbol>  [→ <carrier>]  — <one sentence>.`, the
# carrier clause described below being optional except where it is not.
# The header path is
# relative to the include root, so it starts with `crucible/`.  The entry
# is keyed by the (header, symbol) pair.  Every declaration of that name
# inside that header is one row, so a template dropped with its
# specialisations, or a class with its forward declarations, takes one
# line.  A name that several superseded headers declare takes one row per
# header, because a bare name is not an identity.  Keyed by the name
# alone, one row silenced every header that declared it: three unrelated
# runtime_smoke_test functions in three namespaces shared one sentence,
# and the row for the effect aliases silenced the polynomial one.  The
# sentence is the audit surface: write what happened to the symbol, not
# what the surrounding subsystem does.
#
# The carrier clause
# ------------------
# A row may name its carrier between the key and the em dash:
#
#   <header>:<symbol>  → <new-tree header>  — <one sentence>.
#   <header>:<symbol>  → none  — <one sentence>.
#
# The carrier is the header of the new tree that accounts for the type:
# the one that ports it under another shape, or the one that records why
# it was not carried.  The path is repo-relative, starts with a new root
# (include/foundation/ or include/fixy/), and the guard requires the file
# to exist, so a carrier that moves or is deleted fails as MISSING CARRIER.
#
# The clause is REQUIRED when the old header only forward-declares the
# symbol (an opaque class, struct, union or enum declaration, with no
# definition, alias, concept or specialisation of that name in the same
# header).  Such a header never owned the type, so its row is a deferral
# by construction, and a deferral that names nobody lets the ledger stay
# green while the type itself is assigned to no one: completeness per row
# does not compose into completeness per type.  The guard decides this
# from the code, not from the sentence, and reports a row without the
# clause as UNCARRIED DEFERRAL.
#
# `→ none` is the honest form for a type no header carries yet.  Those
# rows are pinned BY NAME in the guard (uncarried_pinned in
# scripts/check-port-completeness.sh): a `→ none` row the guard does not
# pin is UNPINNED, and a pin with no such row is STALE.  The set can only
# change by editing that list, so it shrinks in the same commit as the
# port that gives a type a carrier, and one name cannot silently replace
# another the way it could under a count.
#
# An entry is checked in both directions, so this file drains in lockstep
# with the code, the way the syscall allowlist does:
#   - STALE:    the header no longer declares the symbol — remove the entry;
#   - OBSOLETE: the symbol now exists in the new tree — it is no longer a
#               drop; remove the entry.
# Either is exit 2 from the guard.
#
# To add an entry, run `scripts/check-port-completeness.sh --emit-drops`:
# it prints a template line for every current miss.  Replace the angle-
# bracket placeholder with the sentence.  Do not add an entry to make the
# guard green; add it because the symbol has no business in the new tree.
#
# A gap is not written as a sentence that points at future work.  A type
# the port has not reached is a `→ none` row pinned in the guard, and the
# row drains when the guard reports it obsolete, which is how the
# monotonic clock's gate and clamp came back to fixy/os/Time.h and the
# five named contexts came back to foundation/effects/Ctx.h.
