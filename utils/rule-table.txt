# The rule table of the base layers and of the quarantine.
#
# The quarantine plugin of utils/tools/quarantine/ reads this table through
# utils/tools/quarantine/rows.h, and the Python rules read it through
# utils/assay/core/ruletable.py.  So each rule has one source.  The two readers
# obey the rows grammar of utils/assay/core/rows.py, and the rule rows-readers
# compares them.
#
# THE FORMAT
#   One row on each line.  A space or a tab divides the words of a row, and a
#   row holds no other white-space character.  A line that starts with '#' is
#   a comment, and an empty line is no row.  A row can end with '| REASON'.
#   An admit row, a home row, an owner row and a syscall row must have a
#   reason, and an ENTRY has one admit row at most.
#   A RANK and an arity N are runs of the digits 0 to 9, with a value of at
#   most 2147483647.  A PATH is relative to
#   the source root.  A PATH that ends with '/' is a directory, and each other
#   PATH is one file.  A PATH that starts with @build/ names a file that the
#   build writes, such as a generated header, by its path inside the build
#   directory.  The name is the same in each build directory, and only a
#   quarantine row and an enforce row can hold it.  A HEADER is a name in
#   angle brackets, as an #include directive spells it.
#
# THE ROWS
#   layer NAME RANK PATH...
#       A layer of the base.  Each file under a PATH of the row is a base file
#       of the layer.  A base file can include a header of its own layer and
#       of each layer with a lower RANK.
#   allow LAYER HEADER [until FAMILY]
#       A file of LAYER, and a file of each layer with a higher RANK, can
#       include the header HEADER.  Each other header that is not in the
#       source root is a finding in a base file.  With `until FAMILY`, the
#       family of the base replaces the header, and each such include is a
#       finding of the kind replace-pending:HEADER.  The ratchet refuses a new
#       include, and an enforce row of the scope include does not make the
#       finding an error.  A file of the language reads no row with `until`
#   door HEADER OWNER
#       The file OWNER is the one file of the source root that can include
#       the header HEADER.  The rule door-unit refuses an OWNER that is a
#       header, and a door file whose include closure holds the Linux UAPI
#       headers and the headers of the C library (utils/tools/quarantine/
#       include.cpp, THE DOOR UNITS).  It also refuses a row whose OWNER does
#       not spell an include of HEADER.
#   admit ENTRY [RESTRICTION...] | REASON
#       A quarantined file can name the standard library entity ENTRY.  A
#       file of the language reads the rows as a language row tells, and each
#       other base file reads them in the same way in its sentinel unit (THE
#       BASE KINDS of utils/tools/quarantine/plugin.h).  Each restriction
#       comes one time at most, in any order, and `in` comes last:
#         until FAMILY  The family of the base that replaces the entry.  The
#                       row goes when that family lands, and `rg 'until
#                       FAMILY'` finds the rows of one family.
#                       The rule admitted-audit makes sure that each such
#                       row has the verdict REPLACE of that family.
#                       Each use that the row admits is a finding of the kind
#                       replace-pending:ENTRY, so the ratchet refuses a new use
#         arity N       The entry admits only a function with N parameters
#         parameters    The entry admits its class only as the type of a
#                       parameter.  The names in the class stay admitted
#         plain-result  The entry admits only a function whose result type
#                       holds no bool, no enumeration and no class with the
#                       annotation foundation::core::closed_tag: not the type
#                       itself, not an element of an array and not a member or
#                       a base of a class.  A dependent result type is refused.
#                       A call of such a function whose result holds the tag
#                       of a sum is the error forged-tag in each file
#         consteval-only
#                       The entry admits only a consteval-only class and the
#                       members of one: a class that holds a std::meta::info,
#                       such as std::vector<std::meta::info>.  The language
#                       permits such a class only in a constant evaluation.
#                       A dependent type and a dependent name are refused
#         concepts      A header admits only the concepts that it declares
#         unless MACRO  The plugin refuses each unit that defines MACRO
#         in PATH...    The entry admits only in the files under the PATHs.
#                       Each PATH is a path of the base, so the row admits
#                       nothing in a quarantined file.  The plugin reads a
#                       file of the language (a language row), and each
#                       other base file in its sentinel unit, and the row
#                       admits in one under a PATH
#       A qualified name admits the entity and each name in it, such as
#       std::tuple_size<T>::value for std::tuple_size.  It admits no other
#       name that starts with the same text: std::tuple_size_v needs its own
#       row.  A friend function that a class defines, such as operator< of
#       std::strong_ordering, is a function of the namespace of the class.
#       Only a row that names the class and the friend exactly admits it,
#       such as std::strong_ordering::operator<, and the row of the class
#       does not admit its friends (utils/tools/quarantine/library.cpp, THE
#       FRIENDS OF A CLASS).  A header admits each entity that the header
#       itself declares: the file that an #include of that exact name enters,
#       and not a header with the same last name in a different directory.
#   quarantine PATH
#       Each file under PATH is quarantined.
#   host PATH... | REASON
#       Each file under a PATH is a file of a host build tool that links a
#       foreign API, such as the tree API of GCC.  The quarantine rule does
#       not apply to it, and the reason tells why.  Another tool joins only
#       with a row of its own and its reason.  No PATH holds a base file
#   kernel PATH... | REASON
#       Each file under a PATH is kernel C that a different compiler
#       compiles, such as a BPF program that Clang compiles.  The quarantine
#       rule does not apply to it, and the reason tells why.  No PATH holds a
#       base file
#   enforce PATH MODE [include]
#       MODE is report or error.  Each finding in a file under PATH that has
#       error mode is a compile error in each build.  A finding in report mode
#       is a line of the section .crucible.quarantine of the object.  With the
#       word include, the row sets the mode of the three include kinds only:
#       layer-header, door-header and upward-include.  With no word, the row
#       sets the mode of each kind.  One PATH has one row of each scope at
#       most.  A change of the mode of a file compiles again only the units
#       with a finding in that file, and a change of a reason or of a comment
#       compiles nothing.
#   language LAYER PATH...
#       Each base file under a PATH is a file of the language.  It can include
#       a header outside the source root only if an allow row with no `until`
#       gives it to LAYER or a lower layer, and to its own layer.  The type of
#       each declaration in it, also a local one, uses no library class,
#       enumeration or typedef that no admit row admits there.  Each
#       expression in it, also an unevaluated operand, names no library entity
#       that no admit row admits there.  A row with `in` admits in a file of
#       the language under one of its paths.  A row with `until` admits there
#       only with `in`, and each such use is a finding of its pending kind.
#       Each other finding in a file of the language is a compile error in
#       each build.  A PATH is in one language row at most, and it must be a
#       path of the base
#   seal ROOT PREFIX...
#       The include closure of the file ROOT holds no file under a PREFIX,
#       and no file of the closure names the namespace of a PREFIX.  The
#       namespace of a PREFIX has one name for each directory after
#       include/, such as crucible::ledger for include/crucible/ledger/.  Each
#       PREFIX is a directory under include/, and a ROOT has one seal row at
#       most.  The rule detsafe-ledger holds each seal row.  It also makes sure
#       that each ROOT exists, and that each row seals each directory named
#       ledger under include/ and the namespace ledger of each project root
#   heavy HEADER | MEASURE
#   light HEADER | MEASURE
#       The header HEADER outside the source root costs more than the limit of
#       the rule heavy-include of utils/registry.txt (heavy), or no more
#       (light).  MEASURE gives the seconds and the lines of a compile of the
#       header alone, or `unmeasured:` and the reason, and an unmeasured header
#       is heavy.  `loop derive header-costs` (utils/assay/loop/derive/
#       header_costs.py) writes these rows after the marker comment at the end
#       of the table, and no other row can be after that comment.  A file under
#       include/ that includes a header outside the source root with no heavy
#       row and no light row is a finding of the rule heavy-include
#   cite PREDICATE PROCEDURE...
#       A parameter of a refinement type of fixy whose predicate is an object
#       or a type of the class PREDICATE, a qualified name with no template
#       arguments, carries the proof of that predicate.  A precondition of the
#       same function that calls decide::PROCEDURE on the parameter tests the
#       proof again, and the rule refined-pre-subsumption refuses it.  A
#       PREDICATE has one cite row at most
#   grant FILE ALIAS ENUMERATION [DOOR...]
#       The type alias ALIAS of the file FILE names each system call that the
#       code of FILE issues, as an enumerator of ENUMERATION.  The code of FILE
#       is each body of FILE, and each expression that a macro body of FILE
#       spells where a unit expands the macro.  A function of a DOOR file that
#       the code of FILE calls stands for each system call that its body
#       issues.  The rule syscalls refuses each system
#       call of one set that the other set does not hold.  ALIAS and
#       ENUMERATION are qualified names, and each FILE and DOOR is one file of
#       the source root.  A FILE has one grant row at most
#   home CLASS ENTITY [PATH...] | REASON
#       The home of ENTITY in the rule home of the plugin
#       (utils/tools/quarantine/home.cpp): a definition or a specialization of
#       ENTITY stands only in a file under a PATH.  CLASS selects the sites of
#       ENTITY and the kind of a site outside its home: federation, owner,
#       combine, split or trait (THE CLASSES of home.cpp).  ENTITY is a
#       qualified name, or one name for each namespace of that name.  The row
#       also governs each declaration inside ENTITY, and the innermost row
#       decides.  A row with no PATH admits no file, so each declaration
#       inside its entity needs a row of its own.  An ENTITY has one home row
#       at most, and the reason is necessary
#   home-args CLASS ENTITY [PATH...] | REASON
#       A home row of a template that also admits each specialization in the
#       file that defines each of its arguments
#   witness HEADER REFUSAL | TYPE | EXPRESSION
#       The class TYPE of the base attests to a fact that it cannot see, such
#       as a pin, a mapping, a descriptor, a permission or a context.  Its
#       constructor is a door that only a mint or the operation that makes the
#       fact can open.  TYPE is the class as a caller spells it, with its
#       template arguments, and not an alias, because the compiler prints the
#       class in its refusal.  HEADER declares TYPE, as an #include directive
#       names it from include/.  EXPRESSION is a construction that a forger can
#       write, with the raw data given to the constructor.
#       forge::lvalue<T>() and forge::rvalue<T>() give a T& and a T&& of each
#       type, and forge::brand gives a brand.  forge::arena gives a family
#       tag of arenas, and forge::owner::arena a member tag of arenas, whose
#       owner holds its one member arena.  REFUSAL is the refusal of the
#       compiler: private, deleted or no-match.  `loop derive witness-fixtures`
#       (utils/assay/loop/derive/witness_fixtures.py) writes one negative
#       fixture for each row, and the fixture must see that refusal.  The rule
#       witness-roster refuses a class of the base with a door shape and no
#       row.  The full name of TYPE with no template arguments has one witness
#       row at most
#   owner RULE KIND ENTITY [PATH...] [by=FUNCTION] | REASON
#       The sites of ENTITY in the rule RULE of the family owner of the plugin
#       (utils/tools/quarantine/owner.cpp): a use of ENTITY, or of a
#       declaration inside it, stands only in a file under a PATH, and only in
#       the body of FUNCTION when the row names one.  A row with no PATH and no
#       FUNCTION admits no site.  Each other use is a finding of the kind KIND.
#       A use is a call, an address, or a candidate of a dependent call, also a
#       call of syscall() with the number of the macro SYS_ENTITY, and a call of
#       a primitive with the enumerator ENTITY.  ENTITY and
#       FUNCTION are qualified names, and a function of the C library has its
#       own name.  An ENTITY has one owner row of a rule at most, and the
#       reason is necessary.  A ledger row admits no finding of the kinds
#       lifetime-start and outside-door.
#       A row of the rule owners with the kind door-use, testing-use,
#       detail-use or unchecked-use reads the names that the source spells,
#       from the events of the parser (THE NAMES OF THE SOURCE of owner.cpp).
#       For such a row, a use is a name, a using form, a member access or a
#       reflection that names ENTITY or an alias of it.  The ENTITY of a row of
#       the kind detail-use is a top namespace, and each namespace named
#       detail inside it is the entity of the row.  The ledger of the rule
#       owners admits the findings of these kinds
#   syscall NAME... | REASON
#       Each NAME is a function of the C library that issues one system call.
#       A call of NAME, and a call of syscall(), is a finding of the kind
#       raw-syscall of the rule syscalls in a file under include/,
#       src/ or vessel/, outside each directory named test, bench, examples,
#       third_party, external or vendor, and each directory whose name starts
#       with build.  The ledger of the rule gives the capability claim of each
#       such call.  A NAME has one syscall row at most
#   primitive FUNCTION | REASON
#       FUNCTION is a raw system call primitive of the base: a qualified
#       name, whose first argument is an enumerator that names the system
#       call.  A call of FUNCTION is a raw system call of the rule
#       syscalls, with the shape FUNCTION(NAME) for the enumerator
#       NAME, as a call of syscall() is.  A FUNCTION has one primitive row
#       at most, and the reason is necessary
#   deny NAME... | REASON
#       Each NAME is a system call that the base does not issue raw.  The C
#       library owns its state.  A call of syscall() with the number of
#       the macro SYS_NAME, and a call of a primitive with the enumerator
#       NAME, is the kind denied-syscall of the rule syscalls in
#       each file that a build compiles.  No ledger row admits it.  A NAME
#       has one deny row at most, and the reason is necessary
#   linear-door FUNCTION | REASON
#       FUNCTION is a door of the rule must-consume: it ends each linear
#       value of its frame (utils/tools/quarantine/linear.cpp, THE DOORS).
#       FUNCTION is a qualified name with no template arguments, and it
#       names each overload of that name.  A function with the annotation
#       drop_door or detach_door of include/foundation/Linear.h is a door
#       with no row.  These rows are the roster of the other doors, and the
#       rule refuses a row whose function no unit of the build reads.  A
#       FUNCTION has one linear-door row at most, and the reason is necessary
#
# THE LONGEST PATH
#   When the PATHs of two rows hold one file, the longer PATH decides.  A
#   layer row, a quarantine row, a host row and a kernel row decide the class
#   of a file in this way.
#   The plugin gives an error for a file under the source root or in the
#   build directory that no layer row and no quarantine row holds.  A file
#   that no enforce row holds has report mode.  The longest PATH of a row of
#   the scope include or of no scope decides the mode of the include kinds,
#   and for one PATH the row of the scope include decides.
