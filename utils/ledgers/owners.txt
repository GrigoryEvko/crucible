# The ledger of the rule owners: the reviewed uses of a name in a file that the owner row of the
# name does not give as a site.
# A row PATH | KIND | N | HOLDER: SHAPE | REASON admits N uses of the kind KIND in the file PATH.
# HOLDER is the function that holds the use, with the types of its parameters, "macro NAME" for a
# use that a macro body spells, or namespace-scope.  SHAPE is the name or the shape of the use.
# Each row gives a reason, and a reviewer writes it.
#   door-use      a use in production code of host::InitOwner, the owner of the init door, or of
#                 host::BackgroundOwner, the owner of the background door.  Only a process entry
#                 point, or the entry function of a background thread, names the owner
#   testing-use   a use in production code of the testing door foundation::effects::testing, which
#                 mints a context with no key.  A header can use it in its own self-test
#   detail-use    a use of a detail namespace of foundation or fixy in a test file.  Only a file
#                 under test/ and outside test/fuzz/ can have such a row
#   unchecked-use, access-alias, access-reflection and member-splice
#                 a reviewed reflection walk under std::meta::access_context::unchecked().  A row of
#                 a walk has the value admit, and a file here gives its caller no reflection of a
#                 member that a walk found
# No row admits a finding of the kinds lifetime-start, open-static-member and walked-return.  The
# rule does not count door-use and testing-use in test/ and bench/.  A count above its row fails,
# and a row that admits more uses than the code has passes.  The landing gate lowers it.
# `python3 utils/bin/guard explain owners` tells the rule.
