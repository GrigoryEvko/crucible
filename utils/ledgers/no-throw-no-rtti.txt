# The ledger of the rule no-throw-no-rtti: the throws and the polymorphic classes that a static library
# of the tree holds and that the tree cannot remove.  `python3 utils/bin/guard explain no-throw-no-rtti`
# tells the rule, and utils/assay/guard/legacy/check_no_throw_no_rtti.py reads this file (the test
# no_throw_no_rtti).  One row each:
#
#   @build/ARCHIVE | throw | admit | TEXT OF THE FUNCTION NAME | REASON
#   @build/ARCHIVE | vtable | admit | TEXT OF THE CLASS NAME | REASON
#
# ARCHIVE is the file name of a static library.  A row matches when the demangled name of the function
# or the class holds its text.  A row whose archive the run reads and that matches nothing is stale and
# fails, so the ledger only shrinks.  A throw of std::bad_alloc or std::bad_array_new_length, the failure
# of an allocation inside libstdc++, needs no row.  No command writes this file.
format 1
rule no-throw-no-rtti

@build/libfixy.a | throw | admit | std::_Rb_tree<std::vector<int, std::allocator<int> > | src/fixy/concurrent/Topology.cpp keeps the L3 groups that it found in a std::set<std::vector<int>>.  An insert copies a vector into a new node, and libstdc++ catches a failed allocation inside the node and throws it again.  The probe of the topology catches each throw of its sysfs reads, so no throw leaves it.  A deduplication over the vector of groups, with no set, removes this row
