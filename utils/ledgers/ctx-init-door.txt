# The ledger of the rule ctx-init-door: the uses in production code of host::InitOwner, the owner of
# the init door, and of host::BackgroundOwner, the owner of the background door.
# A row PATH | door-use | N | HOLDER: OWNER | REASON admits N uses of the owner OWNER in the file PATH.
# HOLDER is the function that holds the use, with the types of its parameters, "macro NAME" for a use
# that a macro body spells, or namespace-scope.  Each row gives a reason.
# The init door gives an init context, which permits the effects of process startup, so only a process
# entry point calls it.  The background door gives a background context, which permits the effects of
# a background thread (Bg, Alloc, IO and Block), so only the entry function of a background thread
# calls it, on that thread.  The definition site in include/foundation/effects/Effect.h names each
# owner too, and it has its rows.
# A new use is more than its count, and it fails.  A count above the uses of its row is stale, and it
# fails too.  The rule does not read test/ and bench/, because the test door serves them.  A reviewer
# writes each reason.  `python3 utils/bin/guard explain ctx-init-door` tells the rule.
