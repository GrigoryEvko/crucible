# The ledger of the rule mint-pattern: the reviewed exemptions from the five
# axes of section XXI.  `python3 utils/bin/guard explain mint-pattern` tells
# the rule.  A reviewer writes each row by hand.
#
# One row is `PATH | AXIS-ok | admit | MINT | REASON`.  The axis is one of
# nodiscard, noexcept, constexpr, requires and ctxfit.  A row names the mint,
# never a line, so an edit above the mint does not move it.  PATH is the file
# of the mint.  One row covers each overload of that name in that file,
# because an overload set is one factory with one reason.
#
# The rule refuses a row that exempts nothing, and a row that it cannot read:
#   * A row whose mint meets the axis, or that names no live mint, is stale
#   * A row whose sites each carry their own marker for the axis is
#     redundant, because the marker exempts each site
#   * A row with no axis, an unknown axis, a line in place of a name, or a
#     name that is no mint is malformed.
# So this file only shrinks while the tree stays the same.
#
# An in-source marker is the other way to exempt: a `§XXI carve-out:
# cx=alloc` or `rq=pre` comment directly above the declaration, or a
# `MINT-PATTERN-OK: <reason>` comment on the line that names the mint.  A
# marker exempts constexpr (cx=alloc, MINT-PATTERN-OK) or requires (rq=pre),
# and no other axis.  One exemption lives in one place.
#
# Each row is a structural exemption: a mint that allocates, calls the
# kernel, makes a resource or reads runtime state.  Section XXI lets such a
# mint drop constexpr.  When a mint gets the shape of section XXI, or the
# rule learns a new shape, remove the row.  Before a new row, ask if the row
# describes a limit of the rule.  Such a row is no exemption.  On 2026-09-21
# the rule learned to read a template parameter that a concept constrains,
# and 50 rows went in one change.
#
# The kinds:
#   constexpr-ok  a mint that allocates, calls the kernel, makes a resource
#                 or reads runtime state.  Some rows name a mint that builds
#                 a fixed aggregate in place and allocates nothing.  The
#                 reason of such a row does not apply to its mint, and a
#                 reviewer examines each such row.
#   requires-ok   a template mint with no type-level constraint.  The rule
#                 reads a `requires` clause and a constrained template
#                 parameter as one constraint.
#   ctxfit-ok     a mint that takes a context that no constraint gates, so
#                 the mint takes each context.  `IsExecCtx Ctx` does not gate
#                 the context.  A token mint has no such row.  A new row of
#                 this kind is a defect, not an exemption.
#   noexcept-ok   section XXI admits no noexcept exemption.  A row of this
#                 kind is a defect, not an exemption.
#   nodiscard-ok  a mint whose return value a caller can discard.  A
#                 constructor with a passkey is not such a mint: the rule
#                 skips each `= default` declaration.
