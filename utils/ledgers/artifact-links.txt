# The ledger of the rule artifact-links: the link facts of the programs, the shared libraries and the modules of
# the target all, for each group and each build kind.  `python3 utils/bin/guard explain artifact-links` tells the
# rule, and the head comment of utils/assay/guard/engines/elf/artifact_links.py gives the rules.
#
# The configuration rows of a kind:  configuration KIND kind KIND  and  configuration KIND tier TIER
#   The ledger holds the facts of the build kind KIND (BUILD_DIR/build-kind.txt) on the target tier TIER of
#   utils/assay/core/target.py.  The first configuration is the base.  The largest count of each key over the
#   configurations judges a build of a kind that the ledger does not hold.
#
# A fact row of the base:  @build/GROUP | KIND | 1 | ENTITY | -
#   An artifact of the group GROUP gives the fact KIND ENTITY.  The first directory of the source directory of
#   the target gives the group: vessel, benches, tests, or tools.
# A difference row of another kind:  @KIND | @build/GROUP | KIND | +1 | ENTITY | -
#
# A new fact fails the test.  A row whose fact goes fails too, until the same commit writes the rows of the kind
# again:
#   python3 utils/bin/guard write --rule artifact-links --build-dir build
# The write refuses a new fact without --raise.  The head comment of the rule gives the reasons for --raise.
format 1
