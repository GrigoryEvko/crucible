# The ledger of the rule ctx-testing-boundary: the files that ship and can use the testing door,
# foundation::effects::testing.
# A row PATH | - | N | - | REASON admits N uses of the door in the file PATH, and gives the reason.
# The door mints a context with no key, and each ctx-bound mint checks for a context.  So a use in code
# that ships gives authority that no mint gave.  A header can use the door in its own self-test.
# A new use in a listed file is more than its count, and it fails.  A count above the uses of its file
# is stale, and it fails too, so the ledger becomes shorter when the self-tests leave the headers.
# The rule does not scan test/ and bench/, because they use the test path on purpose.
# A reviewer writes each row.  `python3 utils/bin/guard explain ctx-testing-boundary` tells the rule.
