# The ledger of the rule no-unchecked-access: the functions that can call
# std::meta::access_context::unchecked(), reflect the access context, or
# splice a member of an object (.[: ->[: &[:).
# `python3 utils/bin/guard explain no-unchecked-access` tells the rule.
#
# A splice of a nonstatic data member has no access check, so a reflection of
# a private member writes the private state of a proof.  One row is
# `PATH | KIND | admit | HOLDER: SHAPE | REASON`: it names one kind of use in
# one function of one file, and the reason that the file needs the unchecked
# context.  HOLDER is the function, with the types of its parameters, "macro
# NAME" for a use that a macro body spells, or namespace-scope.  A file here
# does not give its caller a reflection of a member that a walk found.  The
# rule refuses a function that returns one, and the reviewer of each row
# examines the other ways to publish one.  A row that admits no use fails the
# rule, so the list only shrinks.  A reviewer writes each reason.
#
# The rows have three classes:
#   * A closed roster: a walk of the members of a namespace or of a registry
#     class, which a verdict reads to prove that a set is closed.  No such
#     walk reflects a data member of a proof type.
#   * A structure walk: a verdict over each base and data member of a type,
#     which must see the private ones to be sound.  Each gives a bool, a hash
#     or a row, and never the reflection of a member.
#   * A test: a roster or structure walk that a test compares with the walk of
#     production, and the reproducer which proves that the splice still writes.
