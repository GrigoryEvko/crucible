# The ledger of the rule no-unchecked-access: the files that can call
# std::meta::access_context::unchecked() or splice a member of an object
# (.[: ->[: &[:).  `python3 utils/bin/guard explain no-unchecked-access`
# tells the rule.
#
# A splice of a nonstatic data member has no access check, so a reflection of
# a private member writes the private state of a proof.  One row is
# `PATH | - | admit | - | REASON`: it names one file and the reason that the
# file needs the unchecked context.  A file here does not give its caller a
# reflection of a member that a walk found.  The rule refuses a function that
# returns one, and the reviewer of each row examines the other ways to publish
# one.  A row whose file no longer opens the door fails the rule, so the list
# only shrinks.  A reviewer writes each row by hand.
#
# The rows have four classes:
#   * A closed roster: a walk of the members of a namespace or of a registry
#     class, which a verdict reads to prove that a set is closed.  No such
#     walk reflects a data member of a proof type.
#   * A structure walk: a verdict over each base and data member of a type,
#     which must see the private ones to be sound.  Each gives a bool, a hash
#     or a row, and never the reflection of a member.
#   * A test: a roster or structure walk that a test compares with the walk of
#     production, and the reproducer which proves that the splice still writes.
#   * A negative fixture that reads the return type of a private member
#     function, so that the fixture follows the production signature.  It
#     keeps the reflection of that one function, and it splices nothing.
format 1
