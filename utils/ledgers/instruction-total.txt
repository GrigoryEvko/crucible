# The ledger of the rule instruction-total: the baseline of the user instructions of the compiles of one
# build.  `python3 utils/bin/guard explain instruction-total` tells the rule, and
# `python3 utils/bin/guard write --rule instruction-total --build-dir BUILD` writes the rows of one
# configuration again.
#
# The facts of a configuration:
#   configuration NAME KEY VALUE
#   The build kind, the target tier and each cache variable that changes the objects of all, as the
#   configuration rows of utils/ledgers/quarantine.txt.  A build with other facts has no baseline here.
#   The KIND cell of each row that follows holds the NAME of a configuration.
#
# The two rows of a configuration:
#   - | KIND | INSTRUCTIONS | objects | REASON
#   - | KIND | INSTRUCTIONS | fixtures | REASON
#   The sum, over each object of the target all and over each negative fixture, of the user instructions
#   of the compiler run of its last real compile, at the last write.  A direct compile and a ccache miss
#   give the same count (utils/assay/core/meter.py, A COMPILE THROUGH CCACHE).
#
# A growth over the warning threshold of the measured rule instruction-total of utils/registry.txt gives
# a warning, and over its error threshold an error.  A fall of more than the warning threshold is an error
# too.  The count covers the template instantiation and the constant evaluation that the bytes of
# utils/ledgers/parse-total.txt do not see.  To accept a growth, raise the baseline in the same commit
# with a reason:
#   python3 utils/bin/guard write --rule instruction-total --build-dir build --reason TEXT
format 1
