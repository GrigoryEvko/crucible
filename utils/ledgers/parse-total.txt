# The ledger of the rule parse-total: the baseline of the bytes that the compiles of one build read.
# `python3 utils/bin/guard explain parse-total` tells the rule.  utils/assay/guard/legacy/check_parse_cost.py
# reads this file, and its --write writes the rows of one build kind again.
#
# The two total rows of a kind:
#   - | KIND | BYTES | objects | REASON
#   - | KIND | BYTES | fixtures | REASON
#   The sum, over each object of the target all and over each negative fixture, of the bytes of each file
#   that its compile reads, at the last --write.  The reason tells why the baseline has its value.
#
# A file row:
#   PATH | KIND | BYTES/READERS | - | -       for a file of the tree, or @build/PATH of the build directory
#   - | KIND | BYTES/READERS | NAME | -       for another file, with the name <system>/PATH
#   The size of one file and the number of compiles that read it, for each file whose product was at least
#   0.05 % of the total.  The rows tell which files a change of the total comes from.
#
# A growth over the baseline gives a warning, and over the error threshold of the measured rule
# parse-total of utils/registry.txt an error.  A fall of more than the warning threshold is an error
# too.  To accept a growth, raise the baseline in the same commit with a reason:
#   python3 utils/bin/guard check --rule parse-total --build-dir build --write --reason TEXT
