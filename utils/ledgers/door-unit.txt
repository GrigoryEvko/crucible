# The ledger of the rule door-unit: the doors that are headers, and the door files that include the
# Linux UAPI headers and the headers of the C library.
# A row PATH | KIND | N | ENTITY | REASON admits N findings of KIND with ENTITY in the file PATH.
# A door is one source file, so no other unit gets its system declarations.  A door file includes the
# headers of one family, because some declarations of the two families conflict.  Each reason names the
# slice of misc/01_10_2026_quarantine.md that moves the door into a source file of src/fixy/os/.
# A new finding is more than its count, and it fails.  A count above the findings of its row is stale,
# and it fails too.  A reviewer writes each reason.  `python3 utils/bin/guard explain door-unit` tells
# the rule, and `python3 utils/bin/guard write --rule door-unit` writes this file.
format 1
rule door-unit
include/fixy/os/Io.h | header-door | 1 | <linux/io_uring.h> | the io_uring door is in the header, so each unit that includes fixy/os/Io.h gets the kernel declarations of io_uring.  The slice Os results (4.1) moves the door into a source file of src/fixy/os/.
include/fixy/os/Io.h | header-door | 1 | <sys/sendfile.h> | the sendfile door of zerocopy_transfer is in the header, and its signature holds ::off_t.  The slice Os results (4.1) takes the system type out of the signature and moves the door into a source file of src/fixy/os/.

In the slice Os results (4.1), the door moves into src/fixy/os/ and makes these system calls with foundation::os::raw_syscall.
