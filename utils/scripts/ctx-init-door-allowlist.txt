# ctx-init-door allowlist — the scopes of production code that may name
# host::InitOwner, the owner of the one door to the init context.
# utils/scripts/check-ctx-init-door.py reads this file.
#
# The door gives an init context, and an init context permits the effects
# of process startup.  So a call of the door from a scope gives that scope
# those effects.  Only a process entry point calls the door.  The
# definition site in include/foundation/effects/Effect.h names the owner
# too, and it has its row.
#
# Each row is `PATH SCOPE [xN] — <why this scope may name the owner>`.  The
# scope is the enclosing function as the parse gives it, or
# namespace-scope, or macro.  The count states how many uses the scope
# has.  A new use in a listed scope is more than the count, and it fails.
# A count above the uses of its scope is stale, and it fails too.
#
# test/ and bench/ are not scanned.  The test door serves them.

include/foundation/effects/Effect.h namespace-scope x3 — declares the owner, makes it a friend of the init key, and defines it with its door.  This is the definition site.
include/crucible/Vigil.h Vigil::Vigil — the constructor loads the scheduler-switch program for the deadline watchdog, and that load waits in the kernel for the verifier.
