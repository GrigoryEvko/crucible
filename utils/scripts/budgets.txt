# utils/scripts/budgets.txt — the thresholds of the compile-time checks that measure a quantity.
# utils/scripts/check_report.py reads this table (read_budgets, classify).
#
# A row:  check | warn | error | unit | what the check measures
#
# A value over the warning threshold gives a warning, which does not fail the check.  A value over
# the error threshold gives an error, which fails it.  A value equal to a threshold does not exceed
# it.  A check that measures time on the shared build host sets its error threshold above the
# noise that the host adds, and states the measured noise in the commit that sets the value.
#
# The targets of the tree: no compile job takes more than 15 s, and no test and no cold fixture
# compile takes more than 10 s.
compile-cpu    | 10 | 20 | s  | the user and system CPU time of one compile job, from the build launcher.  The launcher stops a job at three times the error threshold.  When the record holds an instruction count, compile-instructions holds the error level, and this row gives a warning only
compile-instructions | 55 | 110 | G instructions | the user instructions of the compiler run of one compile job, from the build launcher, in units of 10^9.  The count does not change with the load of the host, and a direct compile and a ccache miss give the same count (utils/scripts/cost_meter.py, A COMPILE THROUGH CCACHE)
compile-first  | 15 | 20 | G instructions | the user instructions of the compiler run of the largest compile of one target of all, in units of 10^9 (utils/scripts/check-build-order.py --check compile-first).  A target over the error threshold that utils/scripts/compile-first.txt does not name is an error on the build host and a warning on a CI runner, and a listed target at or below the warning threshold gives a warning
compile-memory | 2  | 4  | GB | the peak resident memory of one compile job, from the build launcher.  The launcher fails a job over the error threshold that no ledger row admits
link-time      | 2  | 5  | s  | the user and system CPU time of one link, from the build launcher.  The launcher stops a link at three times the error threshold
link-memory    | 0.5 | 1 | GB | the peak resident memory of one link, from the build launcher.  The launcher fails a link over the error threshold that no ledger row admits
function-size  | 64 | 256 | KB | the size of the largest function in one object.  The Debug build with ASan has the largest functions
object-text    | 512 | 768 | KB | the machine code of one object: the sum of its allocated, executable sections
header-alone-foundation | 3.25 | 3.5 | MB | the bytes that one header of include/foundation includes when it compiles alone, from the ninja dependency log of its sentinel.  Each translation unit of the tree reads the base headers, so their row is the tightest
header-alone-fixy | 6 | 6.5 | MB | the bytes that one header of include/fixy includes when it compiles alone, from the ninja dependency log of its sentinel
header-alone-crucible | 7 | 7.35 | MB | the bytes that one header of include/crucible includes when it compiles alone, from the ninja dependency log of its sentinel.  No header includes an x86 intrinsics header, so the Debug and the Release build give the same bytes.  The error threshold is 10 % above the largest header on 2026-10-02, include/crucible/Vigil.h with 6.68 MB
test-time      | 5  | 30 | s  | the wall time of one test in one ctest run, from the test launcher for an executable test, and for another test from the log of the run, which ctest gives to utils/scripts/check-test-time.py after the tests
test-memory    | 0.5 | 1.5 | GB | the peak resident memory of the largest process of one executable test, from the test launcher
fixture-cpu    | 5  | 15 | s  | the user and system CPU time of one negative-fixture compile that the result store does not hold (test/neg_compile_driver.py).  The kernel splits the CPU time of a process by tick samples, so a short compile can get 0 s of user time.  When the compile has an instruction count, fixture-instructions holds the error level, and this row gives a warning only
fixture-instructions | 28 | 45 | G instructions | the user instructions of one negative-fixture compile, in units of 10^9 (test/neg_compile_driver.py)
padded-list    | 63 | 63 | elements | the element count of a fixed list whose element type has a padding bit (utils/scripts/check-padded-lists.py). A count above it gives a finding
heavy-include  | 1.25 | 1.25 | x <meta> | the CPU time of one standard header alone (utils/scripts/header-costs.txt) as a multiple of the time of <meta> alone. A header above it is heavy, and a header under include/ does not include it
header-constexpr-ops | 1000000 | 1000000 | operations | the operations of one constant evaluation in a header that compiles alone, the -fconstexpr-ops-limit of its one-line unit in test/layer. GCC gives no warning form of the limit, so the two thresholds are equal
parse-total    | 2  | 5  | % | the growth of the bytes that the compiles of the objects of all and of the negative fixtures read, over the baseline row of the build kind in utils/scripts/parse-total-ledger.txt (utils/scripts/check-parse-cost.py).  A fall of more than the warning threshold is an error too, so the baseline does not stay above the sum
header-fanout  | 10 | 10 | % | the change of the bytes that one header of include/ includes alone times the units that read it, against its row in utils/scripts/header-fanout-ledger.txt (utils/scripts/check-parse-cost.py).  The check gives warnings only, so the two thresholds are equal
instruction-total | 2 | 5 | % | the growth of the user instructions of the compiler run of the last real compile of each object of all and each negative fixture, over the baseline row of the build kind in utils/scripts/instruction-total-ledger.txt (utils/scripts/check-parse-cost.py).  A fall of more than the warning threshold is an error too, so the baseline does not stay above the sum.  Two clean builds of one tree differ by less than 0.01 % in the sum
total-compile-cpu | 3000 | 3000 | s | the CPU time of the last real compile of each object of all, added (utils/scripts/report-check-warnings.py).  A time total gives a warning only, so the two thresholds are equal
total-fixture-cpu | 3000 | 3000 | s | the user and system CPU time of the last real compile of each negative fixture, added (utils/scripts/report-check-warnings.py).  A warning only
total-test-cpu | 120 | 120 | s | the CPU time of each executable test in its last run, added (utils/scripts/report-check-warnings.py).  A script test has no record.  A warning only
edit-build-instructions | 11000 | 11800 | G instructions | the user instructions of each process of the build after one code edit of a base header, the median of the runs of utils/scripts/edit-loop-gauge.py, in units of 10^9.  Three runs on 2026-10-02 gave 10750 G to 10752 G, so the count does not change with the load of the host
edit-test-instructions | 17000 | 18500 | G instructions | the user instructions of each process of the full ctest run after that build, the median of the runs of utils/scripts/edit-loop-gauge.py, in units of 10^9.  A test that spins runs more instructions on a busy host: four runs on 2026-10-02 gave 15825 G with 7 % of the host CPU time used by other processes, and 16429 G with 21 %
edit-build-cpu | 2500 | 3000 | s | the user and system CPU time of the build after one code edit of a base header, the median of the runs of utils/scripts/edit-loop-gauge.py.  A warning only when the step has an exact instruction count.  The warning threshold is the target of 2500 s for each step at 192 jobs
edit-test-cpu  | 2500 | 5000 | s | the user and system CPU time of the full ctest run after that build, the median of the runs of utils/scripts/edit-loop-gauge.py.  A warning only when the step has an exact instruction count
edit-build-wall | 15 | 25 | s | the wall time of the build after one code edit of a base header at 192 jobs, the median of the runs of utils/scripts/edit-loop-gauge.py, judged only when other processes used at most 10 % of the host CPU time in each run.  The warning threshold is the target of 15 s
edit-test-wall | 15 | 30 | s | the wall time of the full ctest run after that build at 192 jobs, the median of the runs of utils/scripts/edit-loop-gauge.py, judged only when other processes used at most 10 % of the host CPU time in each run
configure-time | 10 | 10 | s | the wall time of one configure: of the last configure of a build directory from the first line of the root CMakeLists.txt to the last file that CMake writes (utils/scripts/report-check-warnings.py), of a CMake run inside a build of the loop history, and of each configure of utils/scripts/edit-loop-gauge.py.  On 2026-10-02 a first configure took 8.4 s, and a second one 6.3 s, of which the reply of the CMake file API took 1.3 s.  A warning only
noop-build-time | 0.5 | 0.5 | s | the wall time of cmake --build when no edge but the glob check of CMake runs, from the loop history and utils/scripts/edit-loop-gauge.py.  It took 0.2 s on 2026-10-02: 87 ms to read build.ninja, 12 ms for the glob check, and 65 ms to start cmake.  A warning only
build-peak-memory | 128 | 128 | GB | the largest sum of the peak memory of the compiles and links whose wall times overlap, from the records of the build launcher: of a build directory (utils/scripts/report-check-warnings.py), of a build of the loop history, and of the edit build of utils/scripts/edit-loop-gauge.py.  The sum is an upper bound.  The edit build at 24 jobs took 12.2 GB on 2026-10-02.  A warning only
link-count     | 400 | 400 | links | the link records of the build launcher in a build directory (utils/scripts/report-check-warnings.py).  A build of all held 351 on 2026-10-02.  A warning only
total-link-cpu | 40 | 40 | s | the CPU time of the link records of a build directory, added (utils/scripts/report-check-warnings.py).  The 351 links of a build of all took 20 s on 2026-10-02.  A warning only
cache-size     | 1 | 2 | x | the size of one cache under the cache root, as a multiple of its row of LIMITS in utils/scripts/cache_dir.py, from a sample of its files (utils/scripts/check-cache-size.py).  The eviction of each cache holds it under the limit
constexpr-ops  | 33554432 | 33554432 | operations | the operations of one constant evaluation in one translation unit or negative fixture, the -fconstexpr-ops-limit of the build (CMakeLists.txt) and the GCC default. GCC gives no warning form of the limit, so the two thresholds are equal
