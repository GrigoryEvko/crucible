# The linear base: a preliminary design

Date: 2026-10-12. Status: accepted. The five probes of section 10 are done, the owner accepted the decisions of section 11 on 2026-10-12, and phase A is in progress.

## 1. Purpose and the decisions behind it

The base (`foundation` and `fixy`) is a language inside C++ (owner, 2026-10-02). This design makes that language a linear logic. Each resource is a linear value, each program is a proof about its resources, the build checks the proof, and the runtime erases it.

The owner decided these items:
- 2026-10-11: learn from the mistakes of Rust, and do better, safer and with better ergonomics for brands, borrows and protocols.
- 2026-10-12, brands: the invariant and the costs are approved, also the run-time id of 8 bytes.
- 2026-10-12, protocols: approved. Each linear value is consumed exactly once on each path, and a drop goes through a named door.
- 2026-10-12, borrows: approved in principle. The design must also plan memory: fewer allocations, more throughput, a smaller used size. The tree has no garbage collector, so the type system must do the planning.
- 2026-10-12: invest in linear logic and in the behavior of interaction nets, with proofs that the C++ build checks at compile time.

The probes of 2026-10-11 (slices S1 to S8) found five holes that compile today. Section 9 keeps their slices.

## 2. The principles

These rules hold for each type and each rule of the base. A design that breaks one needs an owner decision.

**P1. Each resource is linear.** A resource is a value whose loss or copy changes what the program can prove. Examples are a permission, a session endpoint, a region capability, a memory credit, the return ticket of a loan, and a split receipt. Each path uses a resource exactly one time.

**P2. Sharing is graded and never implicit.** A value with more than one reader carries its count (`!n`) or its fraction. Unbounded sharing is a decision at a named door.

**P3. Identity is static when a scope bounds it, and dynamic when a value is stored or sent.** A static brand cannot leave its scope. A stored or sent identity is a run-time id.

**P4. A borrow is a split with a return ticket.** The ticket is linear. A view stays in a frame below the frame of its owner, except at the two stated exceptions of section 6.

**P5. The types plan memory.** Each allocation spends a credit of a region. A scope or an epoch bounds the lifetime of each region. Each budget is a grade that the compiler adds. The runtime only bumps and resets. It never searches a free list.

**P6. Nondeterminism is explicit.** Each place where the order of events can change a result is a merge that the types name. Each other computation is confluent, so each schedule gives the same result.

**P7. Proofs are erased.** A proof costs nothing at run time. A run-time check exists only where this design names it: the compare of a run-time id, a lease, an epoch check. Each such check has a probe of the rule `codegen-shapes`.

**P8. Unify the checker, not the types.** Ownership, protocol and memory stay separate axes. Session types and CSL permissions compose through the permission set of a handle, and neither absorbs the other. One linearity checker and one escape checker serve all of them.

**P9. A checker is a part of the language.** Each rule has a plant, a control, a witness and a ledger, as the quarantine rules have (CLAUDE.md §XXII).

**P10. Each exit is a named door.** A drop, a detach, the free of a credit and each other exit from linearity is a door that a search finds and that a ledger counts.

## 3. The linear-logic reading of the base

| Resource | Linear-logic reading | Base today |
|---|---|---|
| Permission split and combine | `P ⊸ L ⊗ R`, and the reverse | `mint_permission_split`, `mint_permission_combine` |
| Fork-join | a cut that joins two proofs on one formula | `mint_permission_fork` |
| Session endpoint | a proposition, and the peer holds its dual | `SessionHandle` |
| Scoped borrow | `own ⊸ view ⊗ (view ⊸ own)`: a view and a return ticket | `with_read_view` |
| Region | a linear region capability | `Arena`. `OwnedRegion` is an owner of X1 that holds a `Permission`, and the new capability is a plain token |
| Free memory | a credit token that each constructor spends | none |
| The owner of a value | `own ⊸ value ⊗ credit` | `Box` of `foundation/core/Ref.h`, which is not linear |
| A choice | an additive sum, and a match is the elimination of the sum | `Option`, `Result` and `OneOf` of the Choice family |
| Sharing | a graded exponential `!n A` | none. The QTT carrier has no count, and `SharedPermission` is a copyable share with no bound |
| The loss of a crash | a named weakening door | the crash-stop layer of `fixy/session/Crash.h` |
| Nondeterminism | an explicit merge | MPSC channels, timers, network |

The memory plan of L3 already counts this way. Each tensor has one birth, and the plan frees it after its last consumer. This design gives the same discipline to host data, through types.

## 5. The checker

The plugin enforces the rules. Each rule starts in report mode, gets a ledger of today's findings, and then becomes an error.

| Rule | What it refuses |
|---|---|
| `must-consume` | A linear local, or a linear `&&` parameter, that reaches the end of its scope on some path with no consume. An assignment to a linear object drops its old value, unless each path to the assignment consumed that value |
| `linear-containment` | A class that holds a linear member and is not linear itself. A `std::vector`, `std::optional`, `std::expected`, `std::pair` or `std::tuple` of a linear type, because its operations consume a linear value and the container is not linear |
| `linear-capture` | A capture by reference of a linear object in a lambda |
| `drop-door` | A drop of a linear value outside a named door |
| `linear-forge` | A union that holds a sealed type, and a `start_lifetime_as`, a `bit_cast` or a byte copy into a sealed type. The rule `start-lifetime` already refuses the second route in the quarantined tree |
| `brand-escape` | A fresh brand type in a return type, a member, a static, a `thread_local`, a container element, a function pointer type, an alias, or a `decltype` outside a body. A return type can hold a fresh brand only when the brand is a defaulted template parameter of that function itself |
| `thread-boundary` | A value of a lease local to one thread in a capture or an argument that starts a thread |
| `brand-reentry` | A value of mint site S in a call that can reach S again in the call graph of the unit |
| `view-escape` | A view in a member, a static, a container, an escaping capture or a return, except at the two exceptions |
| `move-while-borrowed` | A move, split, share or consume of an owner while a view of it is used later on some path |
| `net-records` | The plugin writes the components, ports and wires of a composition into the object, and a guard rule checks the whole program (section 8) |

The escape rules are a test of each leaf in the declaration walk of the plugin, which visits each member, static, alias, return type and local. The rule `permission-storage` is the model. A fresh brand is a lambda closure type in a template argument, and it escapes a function when the function made that closure.

A credit (`Hole`) is linear, so `must-consume` refuses a lost credit. A region capability is linear, and its brand is the region brand, so `brand-escape` is the region check of Tofte and Talpin.

**How the plugin reads a body (probe E1).** `must-consume` runs at the event `PLUGIN_PRE_GENERICIZE`, as the expression family does. At that event the C++ statement tree is whole: the scopes, the declarations, the branches, the loops, the switch labels, the returns and the temporaries. The rule walks the paths forward, with the states dead, live, consumed and maybe, and with a fixed point for each loop. A call that does not return ends a path. The rule skips each clone of a constructor or a destructor, because GCC gives a clone a second event on a lowered body, and the clones gave 40 false findings. The rule reads a base body only in its sentinel unit, and each instance where a unit makes it. A parse build gives the same findings as an object compile.

The prototype of probe E1 found the expected result in each of its 38 plants and controls. It costs 0.20% to 0.63% of the instructions of a compile, 0.31% of the sum of six units, and the plugin of today costs 0.99%.

**Two blind spots need a fifth GCC patch.** The rule can only report until the patch lands:
1. GCC replaces a constant initializer with its value before the event. The consume in `auto [a, b] = split(std::move(whole))`, in `with_read_view(std::move(p), ...)` and in `pool{std::move(token)}` then goes away. That gives 32 false findings on the tree, 29 of them on `Permission`. `-fno-inline` and `-fno-elide-constructors` do not stop it.
2. A trivial move assignment of an empty class leaves no target in the tree, so `value = f(std::move(value))` gives a false double consume. The user-provided move assignment of section 6 closes this case for the linear types of the base.

The patch adds two plugin events in the style of patch 0004. A prototype in a copy of the compiler measured them:
- `PLUGIN_FOLDED_INITIALIZER` gives the initializer before the fold and the tree that replaces it. Under gdb, four sites of the front end fold: `store_init_value`, `expand_default_init`, `massage_init_elt` and `build_vec_init`. A template instance reaches the same sites.
- `PLUGIN_EMPTY_CLASS_ASSIGNMENT` gives the target of a trivial assignment of an empty class. `build_over_call` makes the pair of the source and the target, and `convert_to_void` then replaces the target.

With the events, the ported rule sees each consume that the folds and the assignments hid in the plants, and each control keeps its finding. On the 12 units of the blind spots, 29 of the 32 false findings and both false double consumes go away. The 3 findings that stay are moves of single members and the bodies of doors. With no plugin, the patch changes the instructions of a compile by at most 0.015%, less than the spread between runs. A probe in `cmake/PatchedGccProbe.cmake` checks that the plugin header names the two events, as it checks the four patches.

**The findings of the tree (probe E1).** The strict mode gave 609 findings in 982 units: 581 values with no consume, 10 discarded temporaries, 9 double consumes and 8 assignments over a live value. The tests hold 502 of them. 45 of the 63 findings in the base are inside door functions, so the door roster of section 4 removes them. 12 are a `std::optional` or a `std::expected` that holds a linear value. No finding in the base is a real leak. Of 30 findings that the probe classified by hand, 8 are true leaks or double uses, 13 are limits of the rule and 9 are design questions (section 11). 13 of the 17 double consumes and assignments over a live value are the misuse tests that run-time checks catch today, so the rule finds each one at compile time.

**Limits of the rule.** The rule reads one function at a time. A consume through a reference, an accessor or a member call of a door is not visible, so each such door must be in the roster, and the roster must stay small. A partial move out of a local struct needs a state for each field, or the rule refuses it outside a door that splits the struct. A consume that depends on a correlated branch needs a switch or a door. Exception paths are outside the model, and the tree does not throw. A template that no unit instantiates with a linear type gives no finding. The ledger key holds no line of an exit, because a base template repeats its findings in each unit that instantiates it.

Probe E3 found two forgeries that no rule of today refuses. A union of an integer and an `Index` writes an index of any value. Two runs of one mint site share a brand, so a helper that returns a fresh brand gives an index of one run that reads past the end of the other run. The rules `linear-forge` and `brand-escape` close the two routes. Without them, an `Index` is not memory-safe.

## 6. Memory

**Lifetimes.** Each allocation belongs to one of these classes:
- frame: a scope bounds it
- epoch: an iteration boundary of the pipeline or a region of the DAG bounds it
- process: it lives until the end of the program
- unbounded: its size depends on the data and has no bound that the program knows.

**Regions.** A region is a branded arena with a linear capability. A scope or an epoch mints the capability. An allocation in the region is a bump. The end of the scope or the epoch frees the region in O(1). An object has no header, and the region has no fragmentation.

**Credits and reuse in place.** The consume of a linear `Box<T>` gives a `Hole<size, align>` credit. A build of a `Box<U>` spends a credit that is large enough. A loop that builds its values again then allocates nothing in its steady state. The only exit of a credit is a named free door.

**The legal construction (probe E3).** A build is a placement new, and the `Box` keeps the pointer that the new-expression gives ([expr.new]/11). That road needs no `std::launder` and no `std::start_lifetime_as`. The type proves the alignment: `alignof(U)` is at most the alignment of the credit, and the two are powers of two. The storage of a region is not a const object ([basic.life]/12). A const member and a reference member are legal after P1971R0. A run of values comes from one array new-expression over the bytes of the region, and the form that does not allocate has no array cookie. A run of a type that cannot default-construct needs a door that builds one element at a time, and that door needs its own review.

**The shape of a linear type (probe E3).** The probe measured two shapes:
- Shape 1 has a seal member, a trivial move constructor and a user-provided move assignment. The class is not trivially copyable by [class.prop]/1, so `std::bit_cast` refuses it. It passes in registers, and its destructor is trivial. Probe E1 found that a trivial move assignment of an empty class leaves no node in the tree that the plugin reads, so the rule cannot see a drop through it. A user-provided move assignment stays a call in that tree.
- Shape 2 has a move constructor and a move assignment that set the source to null. It passes in memory.

With the doors `always_inline`, shape 1 gives the same instructions as the raw code at Release and at Debug `-O1`. Shape 2 adds 2 to 4 plain instructions at each call that does not inline. A shape-1 class is an implicit-lifetime type, so `std::start_lifetime_as` of it compiles, and only the rule `linear-forge` refuses it. The plan takes shape 1. A linear type keeps one eligible assignment that is not trivial, because the seal of a class with each assignment deleted holds only through a GCC rule and not through [class.prop]/1. Neither shape tests for a moved-from object at an access, and `must-consume` replaces the null test that `Box` of `include/foundation/core/Ref.h` does at each access.

**Budgets as grades.** A function states the bytes that it can take: a constant, or a formula over its sizes. The compiler adds the budgets along the call tree. It adds the budgets of values that live at the same time, and it takes the maximum over branches. At init, the program evaluates each formula with its configuration and reserves one block. At run time, it only bumps. An unbounded size gets a region that grows by segments of a fixed size, with no free of one object.

**Smaller handles.**
- An index `Index<Brand>` has 4 bytes. Its mint checks the range, so a use has no bounds check. The brand stops an index of one graph from working on a different graph. Probe E3 measured an access of 4 instructions, the same as the raw access with no check. The raw access with a check has 10 instructions at Release.
- A view into a branded region is an offset of 32 bits and a count of 32 bits, 8 bytes in place of 16. The frame holds the base of the region one time. An access costs 2 more instructions and one indexed load. The compact view is only for a stored table of views. An argument takes the 16-byte `View` of the Region family. One door holds the only conversion from an offset to a pointer, and that door calls `__builtin_launder`, because the compiler does not refuse a missing launder.

**A brand across a unit.** A source file cannot name a fresh brand. A function of a source file takes a `View` and checks it again, through a door `view()`. A table that stores indexes keys them on the run-time id of the brand, because the type of a fresh brand is a `decltype` that `brand-escape` refuses. GCC prints each lambda brand as `<lambda()>`, so a brand needs a name for its diagnostics.

**Frame regions.** A frame region gives `[[indeterminate]]` to its buffer, after the name of the variable. Without it, `-ftrivial-auto-var-init=zero` writes the full buffer at each entry to the frame. The ASan poison of a credit needs a door of `foundation/os` with `[[gnu::access(none, 1)]]`, because `-Werror=maybe-uninitialized` refuses the call without it. ASan sees no object of less than 8 bytes.

**Leases.** A view in a frame costs nothing. A stored reference to an owner that lives longer gets an epoch lease: the owner can end only at an epoch boundary, so one check in each epoch replaces one atomic operation in each lease. A lease that the types prove local to one thread needs no atomic operation. The rule `thread-boundary` holds that proof, because C++ has no equivalent of `Send`. Each reader acknowledges an epoch boundary before the owner frees the region.

Probe E3 measured each lease on core 90, 12 runs of 2,000 batches of 10,000 operations, with a spread of the p50 across runs of at most 0.4%:

| Lease | p50 | p99.9 |
|---|---|---|
| Raw pointer | 0.277 ns | 0.290 ns |
| View in a frame | 0.277 ns | 0.290 ns |
| Local to one thread | 0.438 ns | 0.452 ns |
| Epoch, one open | 0.469 ns | 0.484 ns |
| Shared, two locked operations, no contention | 8.712 ns | 8.735 ns |

An epoch lease opens one time in each epoch, so its cost for each access is almost zero.

**The two exceptions of `view-escape`.**
1. A function can return a view of a parameter that `[[quarantine::lifetimebound]]` marks.
2. A class that cannot move or copy can hold a view of a member that it declares first.

**Ring sizes from protocols.** The asynchronous fragment of `fixy/session/Subtype.h` states a channel capacity. That capacity becomes the static size of the ring.

**Layout by reflection.** Reflection gives the field order with no padding, a struct of arrays from a type, and a split of hot fields from cold fields by an annotation.

**The census of the tree (probe E2).** The parse tree of `include/`, `src/` and `vessel/` gives 284 allocation sites that run, and 98 of them run in production. The 98 sites split in this way:
- 35 lexical sites: a scope bounds them
- 13 epoch sites: the build of one iteration bounds them
- 10 sites whose end a lease of a DAG region decides
- 40 sites that run at init, or that grow to a cap.

Regions with a scope and an epoch cover 88 sites. A region for each DAG region, with a lease, covers the other 10. These facts change the design:
1. No arena of the tree resets, and the background arena grows by approximately 13.7 MB in each iteration of SD1.5. The epoch region comes first in phase C, because credits and budgets give nothing while the arena only grows. The arena reset lands before phase C, because plan unit G3 moves the arena into the Ref family.
2. Two kinds of epoch are necessary. A FIFO epoch holds the data of one iteration build: the `TraceGraph`, its CSR and the scratch of the memory plan. It ends at publish. A region for each DAG region ends when its last lease ends, and these ends are not in the order of creation. A region of fixed segments reuses its segments through a stack of equal blocks. That stack searches nothing, so P5 permits it.
3. The pipeline messages (`BgTraceBatch`, `BgBuildWork`, `BgGraphPublish`) repeat with one size, and the channel depth bounds the live count. A slab of depth + 2 messages, with the credits sent back on a return channel, removes each `malloc` and `free` of the pipeline.
4. The publish stage computes the memory plan, so it knows the pool size before the foreground sees the region. If the publish stage allocates the pool and gives it with the region as a credit, the activation on the foreground allocates nothing. The foreground breaks HS10 at this time: the pool allocates at each activation and divergence, and the schema table allocates at the first sight of an operator. A fixed text area for the 512 schema names removes the second case.
5. The scratch of the graph build has a cap of 2^30 slots, too large to reserve at init. It needs a configured bound of operations for each iteration, or a region of segments.
6. Two pointers into the arenas live longer than each lease of today: the queue of regions that wait for compile and the weak entries of `RegionCache`. A free of a region at the end of its lease makes them dangle, unless they hold the lease.

The scan sees only an allocation that the source spells. A link-level count, from the imports of the rule `artifact-symbols` or from a counter of `malloc` in a recorded run, can close that gap.

## 7. Protocols

The session layer keeps its design (the fourteen rules of the session design memory). `must-consume` replaces the run-time check of a dropped handle. `Transferable`, `Returned` and the holds of a session carry the run-time id, so a send keeps the identity.

The default policy of a session stays `check::Enforced` through phases A to D (probe E5). The run-time check also sees a leak and a deadlock across two sessions, which `must-consume` does not see. After phase E, the policy changes to Off for one handle type at a time, and only for a type that has no admitted row. A handle then shrinks from 3 words to the size of its resource.

## 8. Interaction nets

**The model.** An interaction net is a graph of agents. Each agent has one principal port and some auxiliary ports. A rule fires only where two principal ports meet, and it replaces the pair with a small net. When each pair of agents has at most one rule, each step commutes with each other step (Lafont, 1990).

**What the model gives the base:**
- The deadlock check is a priority order: one priority for each action, as Padovani and then Dardha and Gay give it. Probe E4 found that the priority check admits each safe case of its tests and refuses each deadlock. It is the run-time rule of `fixy/session/Watch.h` at compile time, with a priority for each action in place of one for each session. It also admits a wait sequence a, b, a that Watch refuses.
- The criterion of Danos and Regnier alone is the wrong deadlock check. It refuses safe cycles: two sessions in a fixed order, a ring with one queue for each pair, the loop between the Vigil and the pipeline, and a capture that two bodies share. The criterion is the forest check for the parts that have the shape of a fork tree. A multiparty session is one coherence node, and not a triangle of binary wires, because the criterion refuses a live global type in that form.
- A read that two bodies share needs the grade `!n` inside the net, as a contraction agent.
- A reduction that a net describes gives the same result in each schedule. A float reduction tree fixes the order of its operands by port position, so each thread count gives the same bits. Probe E4 reduced a tree of 2^20 floats as a net in FIFO, LIFO and random order, on 1 and on 4 threads. Each run gave the bits of the plain tree sum, and a left fold gave different bits.
- No agent copies or drops by itself. A copy is an explicit agent, so the zero-copy rule becomes a check.
- A rule table where each rule keeps the count of agents or makes it smaller gives a reduction that allocates nothing. A consteval pass over the table proves it.

**Where the base uses it.**
1. As the checker of concurrency topologies: pipelines, fork trees, protocols between Keepers.
2. As the specification of deterministic reductions and rewrites. Generated or written code implements the net. Probe E4 measured an executor of nets at 9.41 ms p50 against 0.872 ms for the plain recursive sum, approximately 11 times slower, with a spread of 9.9% across runs. The plan therefore keeps only the checker, and plain code implements each net.
3. As the per-function linearity proof, which `must-consume` is.

**Where the base does not use it.** Most of Crucible is not graph rewriting. The base does not force a computation into a net.

**How the C++ checks it.**
- Agents are types, and rules are functions with an annotation. GCC 16 reads the annotations of P3394 on a class, a function and a data member. The type of an annotation is `T const`, so a compare with `^^T` finds nothing.
- A consteval checker reads the rule table by reflection. It refuses a second rule for one pair, a right side that drops a port or changes a type, and a right side with more agents than the pair, which is a step that allocates. It also refuses a pair of dual principal ports with no rule, because the net then stops.
- A net inside one unit is a constexpr graph. The check uses union-find over fixed arrays, inside the budget of §XV rule 10. The probe checks the criterion by contraction in O(P log P) for P ports, and not with the linear algorithm of Guerrini.
- A net across units uses the records of `net-records` and a guard rule, with no constexpr cost. The quarantine plugin writes the components, the ports, the wires, the actions and the escapes into its section, from the mint calls and the body walk of phase A. The guard rule joins the wires by channel type and mint site with a union-find, and runs the forest check and the priority check.
- Each error names the agent and the port, in one line of a `static_assert` message. An example: `net: port 'kids' of agent 'join' (node 7) has no wire; each port has exactly one wire`.
- A verdict is a constant at namespace scope. 23 constexpr verdicts in one function cost 22.8 s of debug-information work at `-O1 -g`.

Probe E4 measured the cost of the criterion with the operation limit and the instruction count of the compile:

| Net | Smallest operation limit | Instructions added to the compile |
|---|---|---|
| 11 agents | 11,200 | 17 M |
| 101 agents | 125,440 | 80 M |
| 1,001 agents | 1,269,760, 3.8% of the limit of §XV rule 10 | 0.73 G |
| A ring of 1,000 roles and 4,000 actions, with priorities | 1,417,216 | 0.88 G |

The cost is linear in the size of the net. A real topology of the tree has 2 to 14 agents, so each check adds less than 25 M instructions. The rule table check adds 114 M instructions, most of it in the `std::vector` that each lookup of an annotation builds. The probe measured literal nets, and the cost of a net that reflection builds from a real pack of stages is open.

**What the check finds in the tree.** On the declared parts of production code, the net check finds nothing new. It finds two gaps of `StageGraphWellFormed`: it admits a stage input with no edge, and an output port with two edges. The diamond of `test_pipeline_dag.cpp` uses the second gap. The loop between the Vigil and the pipeline goes through plain atomics and not typed channels, so no net check sees it.

**The pinned deadlock across two sessions.** The mints of `two_forked_sessions_in_a_cycle` declare two separate trees, and the forest check admits them. The program moves the endpoints through a global slot, and that move closes the cycle. With the moves declared, the forest check and the priority check refuse it. So a net check is sound only after phase A refuses a linear endpoint in a static, on the heap, in a shared member and in a capture by reference. Without that rule, the net misses edges.

**Open items.** The priority check reads linear action sequences, and a branch or a loop needs more rules. The channel capacity tells whether a buffered send waits. A lock needs an acquire and a release bracket in the model. Two channels minted at one site differ only at run time. The contraction agents do not model the boxes of MELL, and a net with par groups has no forest check yet.

## 11. Decisions after the probes

The owner accepted each recommendation of this section on 2026-10-12, and phase A started that day.

1. **The placement of the linear core.** Recommendation: the placement of section 4, which probe E5 found free of cycles.
2. **A counted reference.** Recommendation: the base has no general counted reference. Probe E2 put each of the 98 production allocation sites into a scope, an epoch, a lease of a DAG region or a budget at init, and no site needs a count. A share with a count is the grade `!n`, at a named door.
3. **An executor of nets.** Recommendation: the checker only. Probe E4 measured an executor at approximately 11 times the time of plain code.
4. **The phases in the stages of the quarantine plan.** Recommendation:
   - Phase A lands with item 3 of unit 2d, in Stage 2.
   - Phase B lands with group G3 (Ref and Atomic) of Stage 3, because the run-time id needs the Atomic family.
   - Phase C lands with groups G3 and G4 (Region). The arena reset lands before it, and it is in progress.
   - Phase D lands with slice 4.3 of Stage 4, in which `Borrowed` becomes `View`.
   - Phase E: N1 can land at any time, and N2 lands after phase A.
   - Phase F lands in Stage 4.
5. **A choice with a linear payload.** Recommendation: `Option`, `Result` and `OneOf` of a linear payload give only consumers that take `&&`, and a read through `const&` that consumes nothing. Each arm of `OneOf` can be linear, so the error of a `Result` can give back a resource. `linear-containment` refuses a `std::optional` and a `std::expected` of a linear type.
6. **A handle or an owner that holds a `Permission`.** Recommendation: linear, with a release door. This follows from P1 and from the owner decision of 2026-10-12 on protocols. An affine handle makes its destructor a drop that no door names.
7. **An owner that cannot move.** Recommendation: a pinned class is not linear by containment, because no move can consume it. Its destructor is a door of the roster at the end of its scope, and the escape rules keep it in one scope.
8. **A token that only proves a fact**, such as the arena gate of `BackgroundThread`. Recommendation: a proof type that is not linear, with a brand, passed by `const&`. By P1, a value is linear only when its loss or its copy changes what the program can prove. The copy of a proof of a fact changes nothing.
9. **A closure with a linear capture.** Recommendation: the closure is linear by containment. The API that runs it takes it by value, and the call is `std::move(body)()`, through a call operator that takes `this auto&&`. The rule `linear-capture` refuses a capture by reference of a linear object.
10. **The meaning of `T&&` for a linear `T`.** Recommendation: a parameter of type `T&&` consumes its argument on each path, and the callee consumes it or gives it back by return. The tree already uses `&&` in this way for a loan that returns. A `try_` operation takes its argument by value and returns a `Result` that gives the value back when the operation does not succeed. This needs the linear arms of item 5.

## 12. What does not change

- The eight axioms stay. This design proves BorrowSafe, LeakSafe, MemSafe and DetSafe where it can.
- The base has no garbage collector and no counted reference by default.
- The base has no theorem prover of its own. Its proofs are type checks, consteval checks and plugin rules. The Rocq oracles of the session layer stay.
